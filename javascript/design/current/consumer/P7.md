### Running the brokers

- **Ports.** The container `kafka-js-perf` (apache/kafka:4.3.1) isn't ours, and it publishes port 39192, which is
  the SSL target's default PLAINTEXT port. A run with the defaults would fail to start its broker. So every
  security run passes its own ports, and checks right before it starts that they are free.
  - The SASL target's 39292 to 39294 and the PLAINTEXT target's 39092 are free today.
  - `kafka-perf-local` holds 9092.
  - Nobody stops either container.
- **Names, ports and certificates per agent.** Each agent has its own container names, ports and `SECURITY_DIR`, so
  that two runs can't remove each other's broker or overwrite each other's certificates:

  | Runs of | Containers | Ports | `SECURITY_DIR` |
  |---|---|---|---|
  | the Actor | `kafka-js-test-156a`, `js-tests-ssl-156a`, `js-tests-sasl-156a` | 39400, 39410–39412, 39420–39422 | the Actor's scratchpad |
  | the Critic | `…-156c` | 39500, 39510–39512, 39520–39522 | the Critic's scratchpad |
  | the gate | `…-156g` | 39600, 39610–39612, 39620–39622 | the Manager's scratchpad |

  `security-certs` deletes and rewrites `SECURITY_DIR` on every run, which is why each agent needs its own.
- **Clean-up.** The targets remove their container when the run ends, and they create no networks: each broker is
  on Docker's default bridge. If a run is interrupted, its agent removes only that run's named containers, by name,
  after checking their creation time.
