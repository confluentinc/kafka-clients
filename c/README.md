# C Binding

The C API of the Rust Kafka client. The library and its header come from the
Rust crate built with the `ffi` feature (`../rust`); this directory holds the
CMake project that builds and tests against it, and the C++ gRPC server for
the multilanguage tests.

- **Header:** `confluent_kafka.h`, generated by the Rust build into
  `../rust/target/include/`.
- **Library:** `libconfluent_kafka.a` (default) or the shared library, under
  `../rust/target/<RUST_PROFILE>/`: the CMake cache variable `RUST_PROFILE` is
  `debug` by default, and only that directory is searched.
  The library as it ships is `release-cdylib` (`make -C ../rust build-cdylib`).
- **Naming:** symbols keep the Java namespace, without `clients`:
  `org.apache.kafka.clients.producer.KafkaProducer` →
  `kafka_producer_KafkaProducer_t`. Fallible functions return their value and
  take a trailing `kafka_common_Error_t **out_err`, which must point to NULL on
  entry; on failure they store an owned error there (free it with
  `kafka_common_Error_destroy`) and return NULL, 0 or -1, so test `*out_err`,
  not the value. A NULL mandatory argument (a handle, a string, a list) is
  reported like any other failure, with the error Java throws there
  (`kafka_common_Error_LOCAL_NULL_POINTER`, "<parameter> must not be null",
  unless Java's own check names another); a function with no `out_err`
  aborts the process instead, as does a fallible one given a NULL `out_err`
  when it has an error to store. `_destroy(NULL)` is a no-op. Language
  bindings include `confluent_kafka_bindings.h`, where every function reports
  through `out_err`. Blocking operations come twice: the
  blocking function and a `*_cb` variant that takes a `*_cb_t` plus an opaque
  pointer and returns at once. No Rust thread ever runs a C callback: `_cb`
  completions and delivery callbacks are queued on the client, and
  `<Client>__execute_callbacks` runs the pending ones on the calling thread;
  `<Client>__set_callbacks_notify` installs a hook fired once each time the
  queue goes from empty to non-empty, which may only schedule a pump, never
  run callbacks. `_destroy` runs whatever is still pending, exactly once.

## Status

**In Development:** the API is subject to large changes and the stability is not guaranteed.


## Directory Structure

```
CMakeLists.txt          # Builds the test executables against the Rust library
tests/
├── test_kafka_{producer,consumer,admin}.c   # Unity tests of the real clients
├── test_mock_{producer,consumer,admin}.c    # Unity tests of the mocks
├── test_consumer_callbacks.c
├── test_support.h
├── producer_perf_test.c   # Benchmark, not registered with CTest
└── unity/              # Unity test framework (git submodule)
grpc_server/            # C++ gRPC server for the multilanguage tests
Dockerfile.grpc         # Its image
Makefile                # Targets the repository root's Makefile delegates to
```

## Where commands run

Run the commands below **from this directory**. The Unity submodule must be
checked out: `git submodule update --init c/tests/unity` from the repository
root (`make build` below does it, as do the root's `make submodules` and
`make init`).

## Prerequisites

The C binding links the Rust library with the C API. `make build` below builds
it first; by hand:

```bash
make -C ../rust devel-build-all-features   # debug, what the tests link
make -C ../rust build-all-features         # release, with -DRUST_PROFILE=release
make -C ../rust build-cdylib               # as it ships, with -DRUST_PROFILE=release-cdylib:
                                           # features ffi + platform-verifier, no webpki-roots
```

CMake looks for it under `RUST_PROJECT_ROOT`, which defaults to `../rust`;
pass `-DRUST_PROJECT_ROOT=<path>` to use another checkout.

## Building

```bash
cmake -S . -B build
cmake --build build
```

- `-DLINK_TYPE=shared` links the shared library instead of the static one.
- `producer_perf_test` is built only when librdkafka is found through
  pkg-config: it compares the Rust client (`CLIENT_VERSION=3`, default) with
  librdkafka (`CLIENT_VERSION=2`).

## Running Tests

```bash
cd build && ctest --output-on-failure
```

The C arm of the multilanguage integration suite (`__grpc_c`) runs the Rust
test harness against `grpc_server/`; `make test-integration` builds its image
and runs it (Linux only, Docker required).

## Make targets

`Makefile` wraps the commands above with the native `CFLAGS` CI uses, and builds
the Rust library (of `RUST_PROFILE`, debug by default) and the Unity submodule
first. Run it here, or as `make -C c <target>` from the repository root:

```bash
make build                # cmake configure + build into build/
make test                 # test-unit, then test-integration
make test-unit            # ctest only
make test-integration     # gRPC image + the __grpc_c arm (Linux, Docker)
make test-integration-ssl # the same over SSL (also -sasl-ssl)
make test-integration-native  # the __grpc_c arm with a host-built server
make verify               # what CI runs on Linux; verify-macos on macOS
make producer-perf-test   # env-driven benchmark on the release library (needs a broker)
make grpc-image
make clean
```
