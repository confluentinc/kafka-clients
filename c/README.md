# C Binding

The C API of the Rust Kafka client. The library and its header come from the
Rust crate built with the `ffi` feature (`../rust`); this directory holds the
CMake project that builds and tests against it, and the C++ gRPC server for
the multilanguage tests.

- **Header:** `confluent_kafka.h`, generated by the Rust build into
  `../rust/target/include/`.
- **Library:** `libconfluent_kafka.a` (default) or the shared library, under
  `../rust/target/release/` or `../rust/target/debug/`.
- **Naming:** symbols keep the Java namespace, without `clients`:
  `org.apache.kafka.clients.producer.KafkaProducer` →
  `kafka_producer_KafkaProducer_t`. Most operations come twice: a blocking
  function and an `*_async` variant that delivers its result through a
  `*_callback_t` plus `user_data`.

## Status

**In Development:** the API is subject to large changes and the stability is not guaranteed.


## Directory Structure

```
CMakeLists.txt          # Builds the test executables against the Rust library
tests/
├── test_kafka_{producer,consumer,admin}.c   # Unity tests of the real clients
├── test_mock_{producer,consumer,admin}.c    # Unity tests of the mocks
├── test_consumer_callbacks.c
├── test_support.h
├── producer_perf_test.c   # Benchmark, not registered with CTest
└── unity/              # Unity test framework (git submodule)
grpc_server/            # C++ gRPC server for the multilanguage tests
Dockerfile.grpc         # Its image
Makefile                # Targets the repository root's Makefile delegates to
```

## Where commands run

Run the commands below **from this directory**. The Unity submodule must be
checked out: `git submodule update --init --recursive` (the root's
`make submodules` / `make init` do this).

## Prerequisites

Build the Rust library with the C API first:

```bash
make -C ../rust build-all-features   # or: cd ../rust && cargo build --all-features --release
```

CMake looks for it under `RUST_PROJECT_ROOT`, which defaults to `../rust`;
pass `-DRUST_PROJECT_ROOT=<path>` to use another checkout.

## Building

```bash
cmake -S . -B build
cmake --build build
```

- `-DLINK_TYPE=shared` links the shared library instead of the static one.
- `producer_perf_test` is built only when librdkafka is found through
  pkg-config: it compares the Rust client (`CLIENT_VERSION=3`, default) with
  librdkafka (`CLIENT_VERSION=2`).

## Running Tests

```bash
cd build && ctest --output-on-failure
```

The C arm of the multilanguage integration suite (`__grpc_c`) runs the Rust
test harness against `grpc_server/`; `make test-integration` builds its image
and runs it (Linux only, Docker required).

## Make targets

`Makefile` wraps the commands above with the native `CFLAGS` CI uses. The
repository root's Makefile delegates to it (building the Rust library first);
it can also be run directly:

```bash
make build                # cmake configure + build into build/
make test                 # test-unit, then test-integration
make test-unit            # ctest only
make test-integration     # gRPC image + the __grpc_c arm (Linux, Docker)
make producer-perf-test   # env-driven benchmark (needs a broker)
make grpc-image
make clean
```
