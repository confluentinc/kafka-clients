# Plan: no "Java" in the .NET binding's names

Status: approved.

## Goal

No public name and no library-internal name in the .NET binding contains "Java":

1. The eight JDK exception classes move from `Confluent.Kafka.Java.*` to the root namespace
   `Confluent.Kafka`, as Python keeps its JDK classes at `confluent_kafka`.
2. The library's internal identifiers that contain "Java" get neutral names.
3. The rules record each JDK class's .NET parent, so every future class picks its parent the same
   way.

Out of scope, so they keep "Java":
- Doc comments. They name the Java class or method each type copies, which users need to read the
  Javadoc and reviewers need to check the binding.
- Test method names.
- Design history and `COMMENTS.*.md` files, which are records.

## 1. The namespace move

| Class | Today | After | .NET parent (unchanged) |
|---|---|---|---|
| `IllegalArgumentException` | `Confluent.Kafka.Java.Lang` | `Confluent.Kafka` | `ArgumentException` |
| `IllegalStateException` | `Confluent.Kafka.Java.Lang` | `Confluent.Kafka` | `InvalidOperationException` |
| `IndexOutOfBoundsException` | `Confluent.Kafka.Java.Lang` | `Confluent.Kafka` | `ArgumentOutOfRangeException` |
| `UnsupportedOperationException` | `Confluent.Kafka.Java.Lang` | `Confluent.Kafka` | `NotSupportedException` |
| `ConcurrentModificationException` | `Confluent.Kafka.Java.Util` | `Confluent.Kafka` | `InvalidOperationException` |
| `NoSuchElementException` | `Confluent.Kafka.Java.Util` | `Confluent.Kafka` | `InvalidOperationException` |
| `ExecutionException` | `Confluent.Kafka.Java.Util.Concurrent` | `Confluent.Kafka` | `Exception` |
| `TimeoutException` | `Confluent.Kafka.Java.Util.Concurrent` | `Confluent.Kafka` | `System.TimeoutException` |

This table goes into the rules (§4). No parent changes in this plan.

Files: `src/Confluent.Kafka/Java/**` moves to `src/Confluent.Kafka/<Class>.cs`, and the `Java/`
folder is deleted.

### The generator

The eight classes, and every Kafka error class that extends one of them, are generated by the C#
renderer `rust/xtask/src/error_hierarchy/csharp.rs` (`cargo xtask generate-error-codes`), and
`cargo xtask check-generated` fails on stale output. So this plan **must edit that one Rust file**:
- `cs_namespace`: a `java.*` package maps to `Confluent.Kafka`, and `cs_path` to the project root.
- The emitted internal names of §2.
- Its unit tests (`namespaces_follow_the_folder_rule`, and the assertions that contain
  `Confluent.Kafka.Java.`, `IJavaThrowable`, `JavaToString`).

Nothing else under `rust/`, `c/` or `python/` changes. The Python renderer is untouched.

### Name clash with `System.TimeoutException`

`Confluent.Kafka.TimeoutException` now shares its name with `System.TimeoutException` (and with
Kafka's own `Confluent.Kafka.Common.Errors.TimeoutException`).

- **User code:** a file importing both `System` and `Confluent.Kafka` that writes `TimeoutException`
  gets CS0104 (ambiguous reference) and must qualify it. Nothing goes wrong silently. `DOTNET.md`
  gets a short note with the alias form.
- **Library code:** in any `Confluent.Kafka.*` namespace, a bare `TimeoutException` silently means
  the root class, never `System`'s (outside `Confluent.Kafka.Common.Errors`, where it means
  Kafka's). So:
  - `KafkaFutureImpl.cs` drops its alias `using TimeoutException = ...Java.Util.Concurrent...`.
  - A new source-scan unit test fails on a bare `TimeoutException` anywhere in
    `src/Confluent.Kafka` except in the declarations of the three classes of that name. Library code
    writes `Confluent.Kafka.TimeoutException`, `Confluent.Kafka.Common.Errors.TimeoutException` or
    `global::System.TimeoutException` in full.

### Message text

`Throwable.toString()`-style text prints the .NET full type name, so
`Confluent.Kafka.Java.Lang.IllegalStateException: msg` becomes
`Confluent.Kafka.IllegalStateException: msg` (for example inside an `ExecutionException`'s message).
No test asserts the old text today. The Critic checks that every test asserting such text
uses the new names.

## 2. Internal renames

All of these are `internal` or `private`, so no user is affected.

| Today | After | Where |
|---|---|---|
| `IJavaThrowable` | `IExceptionText` | `Internal/IJavaThrowable.cs` → `Internal/IExceptionText.cs` |
| `JavaToString()` | `TypeAndMessage()` | the interface, `KafkaException`, `QuotaViolationException`, the JDK classes |
| `JavaText` | `JavaText`, kept, as Python's `_java.py` keeps the name | `Internal/JavaText.cs` |
| `JavaText.ThrowableToString(e, m)` | `JavaText.TypeAndMessage(e, m)` | same |
| `_javaMessage` | `_givenMessage` | the JDK classes, `KafkaException` |
| `JavaName(...)` (private) | `ConstantName(...)` | `FeatureUpdate`, `AlterConfigOp`, `ConfigEntry` |
| `JavaGet`, `JavaGetAsync`, `JavaGetNow` | `GetWrapped`, `GetWrappedAsync`, `GetNowWrapped` | `Internal/KafkaFutureImpl.cs` |
| `JavaWait`, `JavaWaitAsync` | `WaitWrapped`, `WaitWrappedAsync` | same |
| `JavaAnswer`, `JavaTask`, `SetJavaTask` | `WrappedAnswer`, `WrappedTask`, `SetWrappedTask` | same |
| `Utf8Marshal.JavaUtf8`, `CreateJavaUtf8` | `Utf8Marshal.QuestionMarkUtf8`, `CreateQuestionMarkUtf8` | `Internal/Interop/Utf8Marshal.cs` |

"Wrapped" means the failure comes out inside an `ExecutionException`, unlike `Get`/`GetNow`,
which throw it as it is. `QuestionMarkUtf8` writes an unpaired surrogate as `'?'`.

The final step is a grep: no code identifier under `src/Confluent.Kafka` contains `Java`.

## 3. Callers

Files that import `Confluent.Kafka.Java*` today: 69 in `src/`, 144 in `tests/`, 3 in
`grpc-server/`, 2 in `soak/`. Each drops the import, since `Confluent.Kafka` is already imported or
enclosing. Where a file needs both timeout classes, it uses an alias. The tests' alias
`JavaTimeoutException` becomes `FutureTimeoutException`.

## 4. Rules and docs

- `dotnet/CLAUDE.md` §2:
  - "No public type is declared in `Confluent.Kafka` itself" gains one exception: the eight JDK
    classes.
  - The JDK paragraph is rewritten: the classes sit at the root as Python's do, and library code
    names `TimeoutException` in full (§1 above).
  - A table records each JDK class's .NET parent, so future JDK classes pick parents the same way.
- `dotnet/CLAUDE.md` §3 (the `KafkaException` hierarchy row): the new namespace.
- `dotnet/.claude/rules/ffi-marshalling.md`: the references to `Confluent.Kafka.Java.*` and the
  renamed internals.
- `dotnet/DOTNET.md`: the namespace, and the `TimeoutException` CS0104 note.
- `dotnet/design/current/STATUS.md`: the namespace.
- `PublicNamespaceLayoutTests`:
  - `NoPublicType_IsInTheRootNamespace` allows exactly the eight JDK classes, and fails on any
    other root type.
  - The JDK rows expect `Confluent.Kafka.<Class>`.
- The root `CLAUDE.md` is not changed.
