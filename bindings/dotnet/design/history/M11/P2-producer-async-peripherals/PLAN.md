## 0 · Scope boundary (READ FIRST)

**M11/P2 = "Group B" — the async peripherals, over the PUSH bridge.** This phase introduces the **first public producer API**, but **only the peripherals** — `Flush` / `Close` / `PartitionsFor`. **All Mode A** (producer C ABI present). **`Send` is DEFERRED to phase C** — the `IAsyncProducer` interface grows **additively** (exactly as `IConsumer` grew M5/P8a→P8b); an `IAsyncProducer` without `Send` in P2 is intentional. **Explicitly OUT of P2:** `Send`, `ProducerRecord`, `RecordMetadata`, the `ProducerRecord_t` mirror, the send-completion pull-pump, and the **ffi §A7 pull-vs-push decision** — **P2 is entirely PUSH; §A7 is decided in phase C only.** The `MockProducer` send-control helpers (`CompleteNext`/`ErrorNext`/`HistoryCount`/`Clear`) are send-driving → phase C; `AsyncMockProducer` in P2 is a functional mock for the peripherals **without** those helpers. **Hard line:** no `src/**`/`src/ffi/**`/`confluent_kafka.h`/Rust-core change — STOP and flag if one seems needed.

## 1 · Objective & context

Ship the producer's async peripheral surface as pure additive Mode-A ports over the **same** callback→`TaskCompletionSource` bridge the consumer already ships (ffi §B7) — no net-new bridge machinery, no new value types. Python's `bindings/python/producer.py` has `flush`/`close`/`partitions_for`; this restores that shape on the .NET side, minus send (phase C).

## 3 · Deliverables

- **Interop (`NativeMethods`):** DllImports for `Producer_flush_async`, `Producer_close_async`, `Producer_partitions_for_async` (+ the sync `Producer_flush`/`Producer_close` for Decision 1), and their `*_callback_t` `[UnmanagedFunctionPointer(Cdecl)]` delegate types. **Reuse note:** the flush/close callback signature `(IntPtr error, IntPtr userData)` equals the consumer `OperationCallback`, and `partitions_for` equals the consumer `partitions_for` delegate — the Actor may reuse the consumer delegate types or define a thin `ProducerCallbacks` mirror (recommend the mirror for module clarity). UTF-8 topic marshalling via `Utf8Marshal`.
- **`NativeProducer` (extend):** internal `FlushWithCallback(ct)`, `CloseWithCallback(ct)`, `PartitionsForWithCallback(topic, ct)` — each: precondition guards (§4) → build the `OperationCompletionSource` (void or `<IReadOnlyList<PartitionInfo>>`), root the GCHandle, `SetHandleRef(_handle)` (span-the-op), submit via the `*_async` P/Invoke with the kept-alive delegate + `GCHandle`-as-`user_data`, return `ocs.Task`. The `partitions_for` callback marshals the owned `PartitionInfoList` via `PartitionInfoListMarshal` (copy-out + destroy) then `CompleteWithResult`. Mirror `NativeConsumer` exactly. **The P1-pinned `NativeProducer.Dispose`/`DisposeAsync` (`Producer_destroy`-only) stays literally intact** — the graceful close (Decision 1) is layered ABOVE, in the public wrapper.
- **Public trio (first public producer API), namespace `Confluent.Kafka`:**
  - **`IAsyncProducer` (partial)** — `Task Flush(CancellationToken = default)`, `Task Close(CancellationToken = default)`, `Task Close(TimeSpan, CancellationToken = default)`, `Task<IReadOnlyList<PartitionInfo>> PartitionsFor(string topic, CancellationToken = default)`, `IDisposable`/`IAsyncDisposable`. **No `Send`** (phase C, additive). XML docs mirror Java `Producer` javadoc for these four.
  - **`AsyncKafkaProducer : IAsyncProducer`** — constructs a real `NativeProducer` from config; each method delegates to `NativeProducer.*WithCallback`; owns the Dispose upgrade (Decision 1).
  - **`AsyncMockProducer : IAsyncProducer`** — constructs a mock `NativeProducer` (`MockProducer_new`); functional for the three peripherals (no send-control helpers — phase C).
- **`Close(TimeSpan)` — §4 nuance:** there is **no `Producer_close_with_timeout` ABI** (verified — unlike the consumer). So `Close(TimeSpan)` is a **.NET-side deadline**: race `Producer_close_async`'s TCS against a `TimeSpan`-scoped `CancellationTokenSource` (linked with the caller's token). On deadline, the awaiter completes (timeout), the native close continues to completion and frees its own rooting (no abort path — §4 cancellation). Mirror the consumer's timed-op handling.
- **The Dispose upgrade (Decision 1 — LOCKED YES):** see §4.
- **Tests (broker-free):** `Flush`/`Close` success round-trip on `AsyncMockProducer` (+ idempotent double-close); `PartitionsFor(topic)` → **success + empty `IReadOnlyList<PartitionInfo>`** on the mock (document populated = integration-only); preconditions (null topic → `ArgumentNullException`; post-dispose → `ObjectDisposedException` — exact messages, §A5/DoD §3); cancellation cancels the awaiter (§4); the Dispose-upgrade round-trip (graceful close→destroy, no double-free/UAF); TFM smoke (net462/net8.0/net10.0). **No send-path allocation-budget test** (no send yet).

## 4 · Decisions (LOCKED) + nuances

**Decision 1 — the Dispose upgrade. LOCKED: YES.**
Upgrade disposal to the graceful path (Java/Python shape — `DisposeAsync` = graceful), layered in the **public `AsyncKafkaProducer`**, ABOVE `NativeProducer`:
- **`AsyncKafkaProducer.DisposeAsync()`** → best-effort `await` `Producer_close_async` (via `CloseWithCallback`) → then dispose the `NativeProducer` (→ its pinned `Producer_destroy`).
- **`AsyncKafkaProducer.Dispose()`** → best-effort sync `Producer_close(out_error)` → then dispose the `NativeProducer` (→ `Producer_destroy`).
- The graceful-close orchestration lives in the **public wrapper** — exactly as the consumer's wrapper orchestrates `close→destroy` before the `SafeConsumerHandle` is disposed (`SafeConsumerHandle.cs:29-34`). This makes disposal shape-correct **and leaves P1's pinned `NativeProducer` teardown (`Producer_destroy`-only) literally intact** — the upgrade is purely additive at the public layer. The **pump-drain stays deferred to phase C** (no send/pump yet). This is the expected evolution of P1's pin (P1 had no `Close`). Best-effort: a close error does not prevent the subsequent destroy (the handle must still be freed).

**Decision 2 — sub-phasing. LOCKED: single P2.**
Ship `Flush` + `Close`(+`Close(TimeSpan)`) + `PartitionsFor` + the Dispose upgrade in **one** phase/loop (no P2a/P2b split). Rationale: the surface is ~4 methods and every bridge/value-type is already shipped, so one interface birth + one loop beats birthing a skeleton then re-extending it.

**Nuance — cancellation (§4, honest limitation):** `CancellationToken` on all three, **best-effort**. The producer has **no `wakeup()`** (unlike the consumer), so a cancelled token cancels the **.NET-side wait** (the `OperationCompletionSource` TCS via `RegisterCancellation`) — the **native op continues to completion** and frees its own `GCHandle` rooting on the dispatcher thread (the callback's `TrySet*` on an already-cancelled TCS is a safe no-op). There is **no native abort path**. Document this in the XML docs and the closed record.

**Nuance — preconditions (§A5):** null `topic` → `ArgumentNullException`; post-dispose → `ObjectDisposedException`; both **before any P/Invoke**; assert exact messages in tests.
